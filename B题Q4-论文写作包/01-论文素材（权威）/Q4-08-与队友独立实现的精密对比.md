## §2 逐维度精密对比

### 2.1 布局 —— **两套判据系统各自认证的产物，不可互换**

| | 我们 28 点 | 队友 21 站 |
| --- | --- | --- |
| 结构 | 方格（提供距离覆盖 + 踏脚石）+ 外推环 1875（提供角度覆盖）| **995 环**（提供距离覆盖）+ **1864 环**（提供角度覆盖）+ 原点 |
| 距离覆盖的依据 | 方格 ≤1000 m | **995 环距场地内任意点 ≤1000 m**（最远是边界点 **805 m**，中心 **995 m**）—— 只需 **8 个点**就买到全域距离覆盖 |
| 角度覆盖的依据 | 外推环 1875 ×15 | 1864 ×12 |
| 内层 | **方格 21 点**（r ≤ 1800）| **只有原点**（r ∈ (0,995) 无任何站） |

**关键机理差异**：队友的 995 环是「**用最少的点买到全域距离保证**」的漂亮构造；
而我们的内层方格既有距离覆盖、又当**路线的踏脚石**。

⟹ 这解释了 §3 的实验结果：**把 21 站单独接到我们的 TSP 路线上，n 大时反而更差**
（内层没有踏脚石，移动 39580 → 46433 m）。

### 2.2 探测/证空判据

· 我们：`covers_arena_dir` = 距离覆盖 ∧ 角度覆盖；要点是**同一几何条件同时管探测与证空**
  （`Q4-05` 的"饱和性"）。设计上我们曾验证「外推环半径必须恰好 1800，差 5 m 就失效」。

· 队友：`certify_points` 把目标圆用 **2048 边形外接**、接收盘用 **1000−1e-4 内接**，
  逐区域判定；残余碎片走 `patch_certificates`（包围盒圆盘 ⊆ 站点凸包 + 全部候选站点 ≤1000−1e-5），
  **先 break 再判不通过**（拒绝而非修补）。独立复跑：`passed=True`、328 区域、
  `missing_area=3.2e-27`；另做 **60000 点独立采样 0 违反、最坏裕量 0.677 m**。

⟹ **两边都可靠，但队友的证书是"可复算的产物"**（哈希锁在 `selection_lock.json`，
`offline_reproduce.py:80` 复核），我们的是一条公式。**他们的做法更适合论文里"可验证"的叙事。**

### 2.3 定位几何

· 我们：`geometry.localization_region` —— ±err 楔形交 + Ω 裁剪，返回 `diameter/.mec`。
· 队友：`code/src/geometry.py` 的 `bearing_halfplanes` + `clip_polygon` + `hull`，
  判据量是 **`float(np.max(np.linalg.norm(prior - point, axis=1)))`**（顶点最大距）。

**两处值得学**：
1. **用顶点最大距而不是半径**：凸函数在紧集上的最大值必在顶点取到 ⟹ 对**任意**
   （含非凸）顶点集都是合法上界，`bound ≤ 20` ⟹ 真源确实 ≤20 m。我们的 `mec_of`
   走的是 MEC，二者等价但他们的**不依赖凸性**。
2. `minimum_circle` 返回前用 `max(r, max|顶点−圆心|)` **再膨胀一次** ⟹ 结构上不可能欠覆盖。

### 2.4 定向信念（`DirectionBelief`）—— **我们完全没有对应物**

他们用一个「朝向未知」的信念集：
· 按 `count=ceil(360/width)` 分箱，方向 `k·width` **恰好铺满整圆**；
· 正向更新容差 `factor = 2·sin(width/4)` —— **正是半箱宽对应的弦长**，不松不紧；
· `no_signal` 只在 **`guaranteed`**（先验全部顶点距测点 ≤ 1000−1e-6）成立时才用来收紧，
  因为此时 `no_signal` **只能由扇区外解释**，丢掉远场那一支是合法的。

独立验证：**5960 次运行 0 次剔除真源、0 次空信念崩溃**。

⟹ 我们用「MEC + `_patho` 共线检测 + `ray_mesh_clear`」打补丁式地处理定向源；
他们是**显式的朝向信念**。**这是他们最值得学的一处。**

### 2.5 信息利用 —— **负证据入账**

| 负事件 | 我们 | 队友 |
| --- | --- | --- |
| `/clear` 失败 | 当作"没清掉"，重试 | **`exclude_disk(prior, point)` 挖掉半径 20−1e-5 的圆** ⟹ 缩小信念（严格保守）|
| `no_signal` | 只用于证空 | 入 `negatives[c]`，参与**负区域细化** `negative_regions='disk'` |
| 横杆两点全暗 | 无 | 用**认证切线**把信念**切半** |

⚠ 他们自己给这条加了护栏：信念半径已 ≤20−1e-6 而清除仍失败 ⟹ **抛错**，
把"信念错了"变成显式失败而不是静默漏清。

### 2.6 路线

· 我们：TSP(NN+2-opt, 多初值) + **滚动重规划**（新源被定位才重解，执行整条）。
  这一条我们做过严格配对（官方 −32.0 s/个，5/5 档方向一致）。

· 队友：`exact_insert` 用 **DP 精确插入**（状态 = 已访问源子集 × 站点前缀 × 最后节点），
  外加 **首站后把整张未访问的网刚性旋转**（0–90°，12 档）取最短 —— 旋转保距且保覆盖证书，
  所以合法。**这是我们没有的巧思**（用一个免费的刚体变换换路线长度）。

### 2.7 清源原语

| 层级 | 我们 | 队友 |
| --- | --- | --- |
| 认证清 | `reg.clear_ok`（R_c ≤ 20）| `d['radius'] <= 20-1e-6` |
| 提前试清 | `early_rmax = 100`（Q4 专用；Q3 是 40）| `trial_radius=40`，目标取**多边形最近顶点内推 18 m** |
| 主动切信念 | 无 | **`crossbar`（横杆条件测距）** |
| 兜底 | `capture` → `corridor_sweep` → 网梯子（多尺度）| `optical_cover`（27.5 m 网格，单元半径 19.4 m < 20）|
| 兜底失败 | 尾段多尺度网（可能漏）| **抛错** |

**我们的 `early_rmax=100` 比他们的 `trial_radius=40` 更激进**，而且我们有 Q4 的
**剂量-响应曲线**做依据（见 §5，这条可以反向提供给他们）。

### 2.8 终止与失败处理 —— **他们更严，我们更稳**

他们的**所有卡死状态一律抛异常**（`Empty position region`、`Certified optical clear failed`、
`Exhausted proven optical cover`、`No certified crossbar reference`、动作上限保护…）。

· 好处：**不会静默漏清**，"信念错了"变成显式失败。
· 代价：**一次边界误判 = 整局失败**（见 §5 的 `ERROR=1.005` 零裕量问题）。

我们是**尾段兜底**：牺牲"必然性"换"能跑完"。**两种取舍各有道理**，但如果要做
"可证明"，他们的更接近；如果要做"稳定交付"，我们的更稳。

### 3.1 设计

| 开关 | 作用 |

**锚点**：副本 A 臂种子 1 / n=14 / dir=1.0 = **7076.613917**，与原包**逐位相同** ✓
（否则副本污染了基线，实验作废）。

**五臂**：

| 臂 | 布局 | 频道轮转 |
| --- | --- | --- |
| A 现行 | 我们 28 点 | 固定 |
| B 队友布局 | **队友 21 站** | 固定 |

### 3.3 判读 —— **三条结论，两条是"不要做"**

**① 队友布局单独搬过来：否决。**
· **符号随源数翻转**：n=12 −87.7（显著）→ n=16 **+86.1**（更差）
· **在 n=16 引入 1 次漏清**（B、D 两臂各 1）—— 这在本题里是**硬失败**，任何速度不换
· 机理清楚：他们的网在 **r ∈ (0, 995) 内只有原点**，
  源数一多，中半径的源离最近站很远 ⟹ 移动 39580 → **46433 m**（n=16）

⟹ **布局不能脱离配套的路线与判据单独搬**。他们的 21 站是
「`exact_insert` DP 路线 + `crossbar` 主动切信念」一起认证出来的产物。

**② `scan_current_first`：采纳。**
· **4/4 配置为负**，且**每个配置 20/20 局全部更快**（效应近乎确定性，t=−18.76）
· **零漏清**，测量集合完全不变、只改同站内的轮转顺序
· 幅度小（−1.2 ~ −2.0 s/个 ≈ −0.2%），但**白拿且无风险**

**③ 加密布局：再次否决。**
· 41 点混合臂 **+2873 s/局、0/4 配置为负**
· 与 `Q4-07` 从相反方向得到同一结论（那里是 65/105 点，这里是 41 点）
· **布局点数是第一位的成本杠杆**（检测与走位同时随点数上升）

### 3.4 ★ 一条方法论教训（本轮又踩一次）

**3 局的小样本给出与 20 局相反的符号**（3 局时 B 是 +73.6，20 局时 n=12 是 −87.7）。
本项目的 §5 早有记录，这次是第三次。**隔离实验的最小样本量应当写进流程**：
**至少 4 个配置 × ≥20 局**，否则不要下结论。

### 5.3 ★ 他们的缺陷 1：`bridge_v4.py:5` 的 numba/coverage 导入次序（**已在两个独立审计中确认**）

```python
import numba  # Load before the read-only v2 module named coverage reaches sys.path.
```

注释的意图是防止 numba 抢先导入到 v2 那个**叫 `coverage` 的本地模块**

但**方向反了**——实测：

    import scipy : coverage 进 sys.modules? False
    import numba : coverage 进 sys.modules? True  → site-packages/coverage

之后 `candidate.py:8` 的 `from coverage import triangle_certificate` 拿到的是

钉住的 `numba==0.66.0` 下可能无害，换版本即崩。

**修法建议**（三种，任选）：
1. 把本地 `coverage.py` **改名**（最彻底，但要动所有 import）
2. 先 `import numba`，**再** `del sys.modules['coverage']`（我用的绕法，已验证可行）
3. 用 `importlib.util.spec_from_file_location` 显式按路径加载本地模块

## §8 结论

**他们值得参考——但要精确区分「学机制」与「搬实现」。**

1. **机制层面**：定向朝向信念、负证据入账、认证式清源、精确插入 DP、
   「先锁定再生成新种子」的验证流程——**这五条都该学**。
2. **实现层面**：**21 站布局不能单独搬**（隔离实测：符号随源数翻转 + 引入漏清）；
   36 个锁定参数是**噪声级选择的产物**，不要当资产。
3. **我们可以反向给的**：Q4 的清源半径剂量-响应曲线（他们的 `trial_radius=40`
   按我们的曲线应取 ~100）；两处工程缺陷的根因与修法；分档官方对照工具。
4. **最大的单点收益**其实很朴素：**`scan_current_first`**——白拿、无风险、4/4 配置一致。
   **大部分"看起来很大的改进"，实测下来都不如这种"确定性小改进"可靠。**
