一、三条铁律

#铁律违反的后果
1先砍后比 —— 30 分钟内 3 题砍到 ≤2 题，再谈优劣三题平行比较 = 时间黑洞
2独立先于讨论 —— 第一轮全程禁言谁先开口谁锚定全队
3定题不可逆 —— 定下后不再回头选题反复是最致命的失血

二、时间表（以 18:00 发题为例）

时段阶段动作产出
18:00–18:30独立速览三人各自读 A/B/C 全文，不交流、不讨论每人一张三题体检卡
18:30–19:00交叉复述 + 硬砍每人 3 min 讲卡，另两人只听不打断；按否决清单砍题3 题 → ≤2 题
19:00–20:00分题深挖（并行）按角色做 60 min 专项体检数据报告 + 模型草图 ×2 + 背景检索 ×2
20:00–20:30打分定题交叉汇报 → 独立打分求和 → 最高者胜定题 + 启动清单
22:00兜底红线若 20:00 未定，按打分表强制定题，禁止再议—

三、第 1 段 · 三题体检卡（18:00–18:30，各自独立填写）

题号能复述吗附件数据第一直觉模型我最怕的点
A能 / 半 / 不能
B能 / 半 / 不能
C能 / 半 / 不能
  • 「我最怕的点」必须写具体技术恐惧（如"偏微分方程不会离散化"），不许写"感觉难"。

四、第 2 段 · 分工矩阵（19:00–20:00，角色并行，不是每题分一组）

角色任务60 min 产出
建模手
（集成电路）		对两题各 25 min 写「第一问模型草图」：变量定义 / 目标函数 / 约束条件两份能写成公式的草图
编程手
（软件工程）		对两题附件全都做数据体检：能否读取 / 行列数 / 缺失值 / 量纲 / 能否出第一张图数据可行性报告
（最快的判别器）
写作手
（数字经济）		对两题各 25 min 做背景与范式检索：现实原型 / 有无成熟解法 / 四问逻辑关系两份背景 + 问题结构拆解
  • 编程手不按题分工，要按「数据体检」这个动作覆盖全部剩余题。数据能不能用，比什么模型都更能决定成败。

五、评分量表（20:00 定题，三人独立打分，不商量）

维度5 分1 分A 题B 题C 题
数据可得性附件齐全，读进来就能算关键数据要自己找 / 猜
模型可解性74 h 内能算出确定结果只能给"思路"，给不出数
答案可验证性有办法判断自己算得对不对无法证伪，只能自说自话
写作展开度四问层层递进，能写满 20+ 页一问就到底，后三问硬凑
能力匹配度队里有人真的懂这个领域三人全无相关经验
合计平票时建模手有最终否决权（模型搭不出来是全队死局）

六、硬性否决清单

  • [ ] 三人中 ≥2 人无法复述题意
  • [ ] 附件缺失 / 打不开，且无公开替代来源
  • [ ] 核心模型三人全都没有任何经验
    （不是"不熟"，是"没听过"）
  • [ ] 需要队里完全没有的实验设备或专业物理背景

出现任一条 → 直接砍掉该题

七、四个高频坑

  • "选看起来简单的" —— C 题看着简单，但所有人都会做，区分度全靠细节，反而最容易平庸。
  • "选队友专业对口的" —— 除非那门专业刚好是核心难点，否则收益远小于模型搭不出来的风险。
  • "数据量大 = 能算" —— 数据量大往往意味着清洗就要花掉一整天。
  • 用 AI 刷三题定选题 —— 第一手直觉会丢，且 2026 新规要求 AI 使用必须申报。

八、定题后 30 分钟启动清单（20:30 前必须开始）

  • [ ] 建模手：符号表 + 5 条模型假设 + 第一问完整数学表达
  • [ ] 编程手：数据清洗脚本跑通，出第一张描述性统计图
  • [ ] 写作手：论文骨架搭好（摘要 / 问题重述 / 假设 / 符号 / 模型 / 求解 / 检验 / 评价），占位符填满
  • [ ] 全队：统一 LaTeX 模板，确认三台机器都能编译

定题那一刻，74 小时倒计时就在烧。不要再"想一想"。

九、AI 使用红线（2026 新规 · 选题阶段自查）

  • 可用：查背景、理思路、找文献、写代码草稿
  • 不得：替代核心建模 —— 目标函数、约束设计、模型选择必须由队员主导
  • 所有 AI 使用必须留痕，赛后需提交 AI工具使用详情.pdf
  • 禁止在贴吧 / 群聊 / 知乎 / 小红书 / CSDN / GitHub 等任何公开平台讨论题目内容
  • 禁止与队外任何人（包括指导老师）沟通赛题
